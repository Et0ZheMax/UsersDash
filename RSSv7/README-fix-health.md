# Диагностика и безопасное восстановление LDPlayer

Страница `/fix` показывает сводку, компактную таблицу с поиском и сортировкой по размеру.
Технические причины и пути скрыты в раскрываемых подробностях. Страница читает текущий профиль целиком, файлы `DST_VMS/config`, каталоги VM и
`ldconsole list2`. Выключенные аккаунты и непривязанные VM не исчезают из диагностики.
Отсутствующий/нечитаемый config и стандартные имена `LDPlayer`, `LDPlayer-7` считаются
повреждением конфигурации. Ошибка чтения профиля или list2 возвращает HTTP 503, а не пустой
«исправный» список. `/api/crashedEmus` и `/api/crashed` сохраняют совместимость массива.

Остановленная VM не считается слетевшей. Проверка запущенного Android выполняет только
`getprop sys.boot_completed` с ограничением времени; отсутствие ответа при старте не запускает
ремонт. Даже Android ready не доказывает работу игры: нужны новые ресурсы/марши в логах.
Кнопка «Обновить» не запускает автофикс, бота или отправку Telegram.

## Неиспользуемые VM и место

Фильтры «Без аккаунта» и «Отключены» показывают разные группы. Непривязанная
VM — кандидат для ручной проверки: это может быть и намеренный ручной эмулятор. Индекс нельзя
считать владельцем: он мог использоваться разными людьми в разные месяцы.

Для каждой VM показано занятое файлами место. Диск в Windows измеряется
GetCompressedFileSizeW с учётом sparse/compressed файлов и кешируется на 120 секунд.
Корневой junction разрешён для чтения; вложенные ссылки не обходятся.
Удаление, отвязка аккаунтов и автоматическая очистка не выполняются.

## Восстановление config

1. Выбрать VM в таблице и нажать «Проверить перед ремонтом» для просмотра плана без записи.
2. Остановить GnBots, gnrestarter и LDPlayer. При работающих процессах запись блокируется;
   Исключение: открытый GnBots разрешён, если в реально выбранном SelectedProfile все аккаунты
   целевой VM имеют Active=false, а restarter и все LDPlayer/headless остановлены.
   Сервис самостоятельно не перезапускает ботов или задачи. Проверки повторяются перед записью.
3. «Восстановить выбранные» или «Исправить проблемные» восстанавливают только повреждённые config.
   Каждый индекс обрабатывается один раз, даже если несколько аккаунтов используют одну VM.
4. Источник выбирается из неизменяемых снимков с проверкой manifest SHA-256 и содержимого:
   имя должно соответствовать текущему профилю, JSON и разрешение должны быть корректны.
   Повреждённые новые снимки пропускаются. Legacy дневные папки сортируются по настоящей дате
   и проверяются по содержимому. Выбор backup_dir не отменяет проверку владельца/содержимого.
5. Прежний config сохраняется с проверкой SHA-256, новый записывается во временный файл,
   выполняется fsync и атомарная замена. Затем сервис заново читает и проверяет записанные байты.
   Межпроцессный OS lock исключает параллельный ремонт; смена профиля/config отменяет запись.
6. В `FIX_BACKUP_ROOT` сохраняются `.before-fix` и журнал `repair-*.json` с источником,
   хешем, откатом и результатом каждого индекса. Частичная ошибка пакета возвращает HTTP 409
   и `ok:false`; успешные элементы явно перечислены. `config_restored` не означает готовую игру.

Диски `data.vmdk`, `system.vmdk`, настройки Active и привязки аккаунтов не меняются.
Слепая полная замена config и удаление/замена каталогов VM отключены. Старые маршруты
`/api/fix/do`, `/api/fix/batch`, `/api/fix/config_batch` используют тот же безопасный механизм.
GET `/api/fix/do` запрещён. API `/api/fix/instances` принимает
`{"instance_ids":[7],"dry_run":true}`; без dry_run выполняет восстановление.

## Проверка и откат

Из корня репозитория (Python 3.12+; production 208 использует Python 3.14):

```powershell
python -m unittest discover -s RSSv7 -p test_ld_config_health.py -v
python -m unittest RSSv7.test_config_recovery -v
```

Тесты создают только временные файлы и mock list2. На Windows сервису нужны права чтения
процессов, конфигов и записи в config/rollback; обычно используется существующая задача RSSv7
с повышенными правами в интерактивной сессии пользователя rss.

Для отката конкретного config остановить бота/restarter/LDPlayer и восстановить соответствующий
`.before-fix` атомарной заменой; путь указан в JSON-журнале. Не возвращать целиком старый профиль.
Для отката кода остановить только RSSv7 с временно выключенным его watchdog, вернуть резервные
версии изменённых файлов, запустить прежнюю задачу и вернуть исходное состояние watchdog.
