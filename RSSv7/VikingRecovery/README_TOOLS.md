# Viking Tools — управление фермами

Единый интерфейс содержит три вкладки: **Восстановление**, **Повторный вход** и **Создание новых ферм**.
Запуск: `run_viking_tools.bat` или ярлык **Viking Tools** на рабочем столе сервера.
Для управления планировщиком требуется запуск от администратора в интерактивной Windows-сессии.

## Восстановление строки GnBots

Вкладка **Восстановление** обновляет существующую строку профиля по постоянному ID записи.
Для удалённой фермы включите **Показать удалённые из архива**, найдите её и нажмите **Восстановить ферму**.
Используется последний дневной архив этого же профиля из `C:\LD_backup\bot_acc_configs`.
Просмотр архива ничего не записывает. При запуске полная строка возвращается из выбранного архива:
сохраняются действия, расписания, реквизиты, дополнительные поля и переключение персонажа.
Архивный номер эмулятора сбрасывается в `-1`, запись остаётся выключенной до успешного входа в игру.

Затем Viking Tools записывает новый свободный `InstanceId`, перечитывает профиль для проверки и включает
восстановленную запись. Подготовленные через UsersDash фермы проходят тот же этап. Существующие записи
обновляются без дублирования; совпадение имени с чужим ID, занятый целевой номер или изменение реквизитов
блокируют операцию. Дубли ID в архиве не выбираются автоматически. Несколько персонажей переносятся вместе
только при подтверждённом общем входе, игровом ID и разных включённых слотах Player.

На время операции GnBots, эмуляторы и задачи перезапуска останавливаются штатным Maintenance.
После успеха, ошибки или отмены инструмент восстанавливает задачи и запуск бота; прежняя незавершённая
остановка требует кнопки **Восстановить работу бота**. Неуспешный вход оставляет созданную строку выключенной.
AutoRecovery и TaskGuard также приостанавливаются: TaskGuard останавливается первым, чтобы не включить
worker во время изменения профиля. Исходные состояния Enabled восстанавливаются после операции.
При установке обновления реальные профили и эмуляторы не меняются.

## Создание ферм

Введите имя, почту, пароль и выберите тариф: Только Фарм (500), Расширенный (1000), Премиум (1400).
Кнопка **Добавить ещё один акк** добавляет строку в пакет. IGG ID необязателен: пустое поле выбирает первый
распознанный ID на экране; введённое значение сверяется по первым пяти цифрам. При неоднозначной сверке
вход останавливается. Полный распознанный ID записывается в GnBots и UsersDash.

Перед остановкой бот проверяет конфигурацию, API UsersDash, наличие тарифных шаблонов, уникальность имён,
права администратора, интерактивную сессию и место для всего пакета. Ввод реквизитов выполняется до остановки
сервера, чтобы бот не простаивал, пока оператор заполняет форму.

При создании:

1. Сохраняется состояние задач, останавливаются задачи/мониторы запуска GnBots, сам GnBots и все LDPlayer.
2. Новые данные подтверждаются в UsersDash, затем в активном профиле GnBots создаётся неактивная запись.
3. Клонируется ID 0, выполняются вход и ожидание игровой карты. Новый экземпляр переименовывается в имя фермы.
4. Применяются действия из действующего тарифного шаблона; записываются новый InstanceId и полный IGG ID.
5. Ферма становится активной после подтверждения UsersDash и проверки профиля.
6. Восстанавливается исходное состояние задач, запускаются GnBots и ранее работавшие мониторы.
7. Проверяется продвижение журнала GnBots; UsersDash отправляет Telegram-уведомление с проверкой доставки.

Выключенные ранее задачи остаются выключенными. Задачи UsersDash/RSSv7, SSH, VPN и CloudPub не отключаются.
В установленной версии AccountLib.dll записи действий с `IsActive=false` вызывают ошибку при подготовке
фермы, поэтому такие действия исключаются из применяемого шаблона. Остальные настройки сохраняются.

## Ошибки, отмена и возобновление

При ошибке или отмене исходные задачи и запуск GnBots восстанавливаются в `finally`. Уже созданные эмуляторы
сохраняются для продолжения; незавершённые записи остаются неактивными. Кнопка **Продолжить пакет** использует
проверенные этапы и ID. Для аварийного завершения самого инструмента предусмотрена отдельная кнопка
**Восстановить работу бота**, читающая `state/maintenance.json`.

Если Windows или питание сервера прервали процесс, восстановление нужно запустить вручную этой кнопкой.
При сбое Telegram завершённые фермы сохраняются, но общий пакет не помечается успешным до подтверждения
уведомления. Повторная попытка доставки может дать дубликат сообщения, если ответ Telegram был потерян.

Журнал `logs/viking_tools.log` не содержит паролей. Незавершённый пакет хранит реквизиты под Windows DPAPI
текущего пользователя, поэтому продолжать его нужно под тем же пользователем. После успеха зашифрованные
реквизиты удаляются из журнала этапов. Перед каждой правкой GnBots создаётся датированная копия профиля
`.before_tools_...`. Резервные копии профиля содержат его штатные учётные данные, как и сам профиль.

## Развёртывание

Рядом с инструментом нужен `viking_tools.json` (пути не содержат секретов):

```json
{
  "rss_config": "C:\\Users\\rss\\Desktop\\RssCounterV8\\GIT\\UsersDash\\RSSv7\\config.json",
  "templates_dir": "C:\\Users\\rss\\Desktop\\RssCounterV8\\GIT\\UsersDash\\RSSv7\\settings\\templates"
}
```

Используются действующие `USERSDASH_API_URL`, `USERSDASH_API_TOKEN`, `SERVER_NAME` из RSSv7/root `.env`.
Токен отправляется в заголовке Authorization. Для удалённого API необходим HTTPS; loopback HTTP допустим.
UsersDash должен включать `UsersDash/services/viking_provision.py` и его регистрацию в `api_views.py`.
Дополнительные зависимости инструмента не требуются: используется стандартная библиотека Python и Tkinter.

Действующие тарифные шаблоны: `OnlyFarm.json`, `Extended.json`, `Premium.json` в каталоге RSSv7 settings/templates.
Данные в UsersDash связываются по стабильному ID операции; клиент определяется по существующему правилу
UsersDash (базовое имя фермы без завершающего номера). Дата оплаты автоматически не назначается.

## Проверка

```bat
py -3 -m unittest discover -s RSSv7/VikingRecovery -p "test_*.py"
py -3 -m unittest UsersDash.tests.test_viking_provision
powershell -NoProfile -File RSSv7/VikingRecovery/test_viking_maintenance.ps1 -Helper "$PWD/RSSv7/VikingRecovery/viking_maintenance.ps1"
```

API-тесты используют изолированную SQLite в памяти. Создание реальной фермы требует её учётных данных и
запуска с рабочего стола. Перед откатом файлов завершите операцию и восстановите работу бота.
Тест Maintenance подменяет задачи и процессы; реальные задачи, GnBots и VM не запускаются и не останавливаются.
