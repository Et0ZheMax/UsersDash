# Запуск и обновление RSSv7

Запуск на Windows: `py -3 RssCounterWebV7.py` из каталога RSSv7 с установленными зависимостями.
Администратор для самой веб-панели не требуется. Настройки загружаются через `shared/env_loader.py`.

Обязательные схемы ресурсов, аккаунтов и логов готовятся до открытия порта 5001.
На уже обновлённой БД повторная дедупликация и заполнение legacy source_id не выполняются:
отсутствие дублей обеспечивают уникальные индексы. Первый переход со старой схемы может занять больше времени.
Ошибки обязательной инициализации останавливают запуск, чтобы API не работал с неполной схемой.

Debug выключен по умолчанию. `RSSV7_DEBUG=1` включает отладчик, но автоперезапуск всегда выключен,
чтобы не запускать два парсера и два набора фоновых задач. Запускайте одну копию панели на одну БД.

Панель сначала читает сохранённые ресурсы, затем вызывает `POST /api/refresh?background=1`.
Запрос возвращает `running`, `error`, `generation` и время последнего успешного разбора `last_update`.
`GET /api/refresh/status` сообщает о завершении без обращения к SQLite. После завершения панель
повторно загружает ресурсы и статистику. Одновременные запросы объединяются в текущий проход.
Обычный `POST /api/refresh` сохраняет синхронное поведение для существующих клиентов.
`POST /api/forceRefreshToday` сохраняет полное перечтение под общей блокировкой парсера.

При ошибке разбора соединения закрываются, а неприменённые смещения не записываются.
Резервные копии и аудит шаблонов выполняются отдельно от потока HTTP.

Проверки без запуска приложения и без доступа к рабочим БД:

```powershell
py -3 -m unittest test_startup_tasks test_logs_startup -v
py -3 -m py_compile RssCounterWebV7.py startup_tasks.py
```

При установке на F99 исходные файлы сохраняются в датированном каталоге `C:\ProgramData\BotOps`.
Для отката остановите только RSSv7, верните `RssCounterWebV7.py`, `startup_tasks.py` и `templates/index.html`
из подкаталога `before-YYYYMMDD-HHMMSS`, затем запустите панель той же командой.
БД и профили для отката кода не заменяются.


Свежее состояние без открытой панели: отдельный daemon-поток обновляет БД при старте
и каждые 60 секунд после завершения прохода. При ошибке повторяет попытку на следующем цикле.
HTTP-запросы присоединяются к тому же проходу и не создают очередь повторных разборов.
После успешного разбора обновляется кэш простоя с `notify=False`; состояние уведомлений
и отправка Telegram при этом не затрагиваются. Часовой монитор сначала дожидается
успешного разбора, затем выполняет штатную проверку. Ошибка парсера не создаёт новые
уведомления о простое на основании старых данных.

Проверка регрессии: `py -3 -m unittest test_startup_tasks test_logs_startup test_refresh_freshness -v`.
